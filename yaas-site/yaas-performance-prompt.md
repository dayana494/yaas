# Задача: поднять PageSpeed Performance на мобильном и десктопе

Цель: Performance ≥ 90 на мобильном и ≥ 85 на десктопе (PageSpeed Insights, https://dayana494.github.io/yaas/). Внешний вид, анимации и поведение сайта для пользователя не должны измениться.

## Исходные замеры (PSI, Lighthouse 13.5)
| | Mobile | Desktop |
|---|---|---|
| Score | 75 | 65 |
| FCP | 1,1 с | 0,3 с |
| LCP | 1,7 с (заголовок прелоадера) | 1,4 с (гигантский «YAAS», `.hero-logo-giant .logo-text`, render delay 1 110 мс) |
| TBT | 1 330 мс | 2 300 мс (0 баллов) |
| CLS | 0 | 0 |
| SI | 2,4 с | 1,2 с |

Что показал разбор:
- **TBT.** Длинные задачи идут после скрытия прелоадера. Больше всего времени — в чанке с GSAP/ScrollTrigger (Vite назвал его `Footer-*.js`): 3,5 с CPU на десктопе, задачи по 696 и 527 мс. На мобильном таких задач 20, по 90–320 мс. В категории «Other» 3–3,7 с: это WebGL-рендер. Lighthouse рендерит программно, без GPU, поэтому каждый кадр холста стоит дорого.
- **Десктоп хуже мобильного из-за пинов.** На мобильном работает `simpleMode` без pin/scrub, а на десктопе создаются и пересчитываются все пины. В `HomePage.jsx` каждый новый триггер вызывает свой `.refresh()` (строки ~247, 279, 302, 316, 326), а потом ещё глобальный `ScrollTrigger.refresh()` (~329). Ещё есть `riseTransition.js:260` и `FlavorDetailPage.jsx:66`. Forced reflow в GSAP-чанке и в `index-*.js` (114 мс).
- **LCP на десктопе.** Гигантский YAAS рисует React (`HeroWordmark.jsx`), и он становится видимым только после прелоадера и входа.
- **Сеть: 2,7 МБ, из них 1,5 МБ ниже первого экрана, но грузится сразу.** Фото сценариев `public/photos/scenarios/*.webp` имеют размер 2560×1446 (140–333 КБ каждое) и ставятся через `backgroundImage` в `ScenarioArcGallery.jsx:425` / `ScenarioCardsIsometric.jsx:137`. Банки контактов `public/images/cans/*.webp` имеют размер 1092×1583 (~145 КБ каждая, `ContactCans.jsx`). PNG прелоадера (`public/images/preloader/*.png`): PSI обещает −63 КБ при переводе в WebP.
- Unused JS 113 КБ в чанке three/drei (`useCanMaterials-*.js`).

## Контекст кодовой базы
- React 18 + Vite 5 + @react-three/fiber/drei + three 0.169 + GSAP 3.12 (ScrollTrigger). Деплой на GitHub Pages (`.github/workflows/deploy.yml`, `VITE_BASE_PATH=/yaas/`).
- Холсты: `src/three/Scene.jsx`, `src/three/FlavorStoryScene.jsx` — `frameloop="demand"`, `dpr={[1, 2]}`. Инвалидация: `src/three/renderOnDemand.js`. Отложенная загрузка чанков: `src/three/deferredLoad.js`, `LazyScene.jsx`.
- Прелоадер инлайном в `index.html`. `window.__yaasPreloader` (`done` / `ready`) синхронизирует прелоадер с входом героя.
- `ThumbnailShot.jsx` работает только при `?shot=`, не трогать.
- Мобильный режим и логику перекрытий определяет `src/scroll/riseTransition.js` (`useOverlapEnabled`, `mobilePinType`).
- Пути к ассетам только через `asset()` из `src/data/assetUrl.js`.

## Что сделать (по порядку, после каждого шага — сборка и замер)

### 1. ScrollTrigger: лениво и с одним refresh (главный рычаг для TBT, особенно на десктопе)
- Пины первого экрана (intro) создавать как сейчас. Пины экранов ниже (Screen 2 arc, scenario cards, advantages, about, footer) создавать не при маунте. Создавать их в `requestIdleCallback` (с фолбэком на `setTimeout`) после `window.__yaasPreloader.done`, пачками, чтобы ни одна задача не превышала ~50 мс. Если пользователь начал скроллить раньше, чем пины созданы, досоздать их синхронно до того, как секция дойдёт до вьюпорта.
- Вместо цепочки per-instance `.refresh()` — один `ScrollTrigger.refresh()` после создания всех пинов. Логику `correctPinStarts` / `slotTop` (коррекция 'top top' после предыдущего пина) нужно сохранить: сначала разберись, зачем там per-instance refresh (см. комментарии ~254–279), и сохрани корректность стартов. Если без per-instance refresh старты съезжают, оставь их, но выполни всю цепочку одним проходом в idle, а не при маунте.
- Разделить чтения и записи DOM (сначала все `getBoundingClientRect`, потом все записи), чтобы убрать forced reflow. Найди источник 114 мс в `index-*.js` (скорее всего, measure в `useLayoutEffect` / resize-хуках) и сделай то же.
- **Проверка:** позиции старта/конца каждого пина до и после совпадают ±2 px на 1920×1080, 1440×900, 1366×768. Выведи таблицу `trigger.start` / `trigger.end` до и после.

### 2. WebGL: дешевле каждый кадр
- `dpr`: `[1, 1.5]` на всех холстах. Во время входной анимации банок (от `done` до конца влёта) — 1, после окончания вернуть до 1,5 и сделать один `invalidate()`.
- Скомпилировать шейдеры и загрузить текстуры в GPU, пока виден прелоадер: `gl.compileAsync(scene, camera)` (three ≥ 0.158) или `gl.compile` + `initTexture` для текстур этикеток. `ready()` прелоадера вызывать уже после этого (в пределах существующего лимита 2 с).
- Убедиться, что во время GSAP-анимаций `invalidate()` вызывается не чаще одного раза за кадр (через rAF-флаг) и что после окончания анимаций рендер останавливается (`frameloop="demand"` реально простаивает). Проверь через счётчик рендеров в dev.
- Банки вне кадра карусели не рендерить (`visible = false` или frustum culling, если сейчас отключён).
- `antialias`, тени и `powerPreference` не менять, если это визуально заметно. Если что-то из этого поменял, приложи скриншот до/после.

### 3. LCP на десктопе: гигантский YAAS в первом кадре
- Гигантский YAAS (`.hero-logo-giant .logo-text`) должен быть отрисован сразу под прелоадером, без стартового `opacity: 0` / `visibility: hidden`. Входную анимацию, если она есть, делать только через `transform`. Если логотип раскрывается маской или clip-path, оставить начальное состояние видимым хотя бы частично. Цель — LCP ≤ 1,0 с на десктопе. На мобильном LCP не должен ухудшиться.

### 4. Картинки ниже первого экрана
- Фото сценариев: сделать версии 1280w и 2560w (sharp/cwebp, quality ~75; для 1280w цель ≤ 90 КБ). Выбор делать через `image-set()` / media query по ширине экрана и DPR: мобильный и ноутбуки ≤ 1440 — 1280w, остальное — 2560w. Фон карточки ставить только когда секция в ~1 экране от вьюпорта (IntersectionObserver, rootMargin ~100vh). До этого — цвет вкуса, как сейчас в фолбэке.
- Банки контактов: ресайз до 2× отображаемого размера (максимум, скорее всего, ~600 px по высоте) и ленивая загрузка, как у фото.
- PNG прелоадера перевести в WebP с альфой (оба размера, `-sm` тоже) и обновить пути в `index.html`. Цель ≤ 15 КБ на файл.
- Исходники не удалять и не перезаписывать: новые файлы класть рядом с суффиксами (`-1280.webp`, `-2560.webp`), старые оставить.

### 5. Unused JS
- Проверить импорты из `@react-three/drei` и `three`: только точечные, без `import * as THREE` там, где хватает именованных. Не выносить three в отдельный vendor-чанк, если это ухудшает загрузку первого экрана.

## Ограничения
- Делай только перечисленное. Никаких рефакторингов, переименований и правок дизайна сверх задач.
- Не менять тайминги, easing, порядок и визуальный результат анимаций (вход героя, пины, DropText, флип карусели).
- Новые npm-зависимости — только в devDependencies и только после вопроса мне. Сначала проверь, что уже установлено.
- Не трогать `ThumbnailShot.jsx`, контент в `src/data/*.js`, деплой-конфиги.
- Не использовать детект Lighthouse / headless / user-agent, чтобы отдавать ему облегчённую версию. Оптимизации должны работать для всех.
- Остановись и спроси, если: пин после изменений стартует не там и за две попытки не получается починить; для цели нужно менять визуал; нужна новая зависимость.
