# Задача: прелоадер для сайта YAAS

Дизайн бери из Figma (используй Figma MCP): https://www.figma.com/design/iBVnVoDHZhsZdJSjgX3IZX/%D1%81%D0%B0%D0%B9%D1%82-yaas?node-id=420-2&m=dev
Из макета нужны фон, цвета, начертание и регистр заголовка, стиль счётчика, композиция и размеры банок относительно фрейма. Размеры фрейма (ширина и высота) считай из Figma.

## Зачем это нужно
При первом заходе видно, как догружаются текстуры этикеток, 3D-банки, заголовок YAAS и фон первого экрана. Прелоадер должен закрыть этот момент и не больше. Метрики загрузки (LCP, CLS, TBT) ухудшаться не должны.

## Контекст кодовой базы (ориентируйся на это, не выдумывай заново)
- Стек: React 18 + Vite + @react-three/fiber/drei + three + GSAP. Входная точка: `index.html` → `src/main.jsx` → `src/App.jsx`. Главная: `src/pages/HomePage.jsx`.
- Шрифты: `Soledago.woff2` и `Bounded-Medium.woff2` уже preload'ятся в `index.html`, а `@font-face` тоже объявлены там. Переменная `--font-display` задана в `src/styles/index.css`.
- Автоскейл: `src/hooks/useHeroScale.js`. Сцена 1200×650, `SIDE_MARGIN = 30`, `scale = min((innerWidth - 60) / 1200, innerHeight / 650)`, результат пишется в `--hero-scale`. Боковой отступ контейнера сайта: `--content-gutter: 30px` (`index.css`).
- Вход первого экрана: `HeroScreen` / `HeroCanRig` — банки влетают, затем `handleHeroEntranceStart` → `setHeroTextVisible(true)` показывает текст (`HomePage.jsx`).
- PNG банок уже есть: `public/textures/thumbnails/{lemon,blueberry,strawberry,orange,apple}.png` (300×400, 100–130 КБ). Пути прописаны в `src/data/flavors.js` → `thumbnail`. 3D-модели не используй.

## Архитектура (обязательно)
1. Разметку, критический CSS и JS прелоадера пиши инлайном прямо в `index.html` на ванильном JS, не в React-компоненте. Так прелоадер отрисуется в первом же кадре, до того как скачается и выполнится бандл, и не будет его ждать. Инлайн CSS+JS: не больше ~3 КБ.
2. Прелоадер — `position: fixed` оверлей поверх `#root`. Контент под ним рендерится как обычно: никакого `display:none` / `visibility:hidden` на `#root`, никаких задержек монтирования React. Пока оверлей виден, скролл заблокирован.
3. Синхронизация с React — через глобальный объект из `index.html`: `window.__yaasPreloader = { done: Promise, ready: () => void }`. `HomePage` / `HeroCanRig` перед стартом анимации влёта банок и появления текста ждут `done`. Если оверлея нет, `done` уже resolved. Логику самой анимации входа НЕ меняй, меняй только момент старта.

## Состав
### 1. Заголовок «loading energy»
- Шрифт Soledago; регистр и цвет как в макете.
- Кегль подбирается так, чтобы строка точно заполняла ширину контейнера: `100vw - 2 × var(--content-gutter)`. Сделай это без JS-замеров на каждом ресайзе: один раз вычисли коэффициент K (ширина строки «loading energy» в Soledago на 1px кегля, по аналогии с константой 2.245 для «YAAS» в `hero.css`) и задай `font-size: calc((100vw - 2 * var(--content-gutter)) / K)`. Коэффициент проверь замером в браузере: ширина текста должна совпадать с шириной контейнера ±2px на 1920, 1440, 1024, 390.
- Отступ сверху — значение из Figma, умноженное на тот же автоскейл, что у сайта. Формулу `useHeroScale` продублируй в инлайн-скрипте, а результат запиши в `--hero-scale` на `<html>` до первой отрисовки (React-хук потом перезапишет то же значение, скачка не будет). Назовём итоговый отступ `--pl-edge`.

### 2. Бегущая строка банок (посередине)
- Картинки: оптимизированные копии `thumbnails/*.png`. Сохрани в `public/images/preloader/`, размер ровно 2× от отображаемого, сжатие через pngquant/oxipng (или sharp, если уже есть в devDependencies). Цель ≤ 35 КБ на банку, без видимых артефактов. Исходники не трогай. Если нужного инструмента нет — остановись и спроси, прежде чем ставить зависимость.
- Размер банки: как в макете, с учётом автоскейла (высота из Figma × `--hero-scale`).
- Банок в ленте больше пяти: повторяй вкусы по кругу в порядке `flavors.js`, пока лента не заполнит 2 ширины экрана. Для бесшовного цикла трек нужно дублировать.
- Движение плавное и медленное: только CSS `@keyframes` с `transform: translate3d`, `will-change: transform`, линейный easing, один полный цикл ≈ 25–35 с (подбери, чтобы выглядело спокойно). Никаких JS-анимаций на каждый кадр.
- `<img>` с явными `width`/`height`, `decoding="async"`, `alt=""`, `fetchpriority="low"`. Банки прелоадера не должны отнимать канал у текстур первого экрана: если банка не успела загрузиться, её просто нет — прелоадер из-за неё не ждёт.

### 3. Счётчик процентов (внизу)
- Логику счёта возьми с https://mt-webdesign.ru/counter-loading (открой страницу и разберись, как работает счётчик), но перепиши на `requestAnimationFrame` без jQuery и без setInterval.
- Стиль и расположение как в макете. Отступ от низа экрана равен `--pl-edge` (такой же, как сверху до заголовка).
- `font-variant-numeric: tabular-nums` (или моноширинные цифры шрифта), чтобы цифры не прыгали по ширине.

## Логика показа и скрытия
- Готовность = `document.fonts.ready` + загружены текстуры этикеток первого экрана и фон + отрисован первый кадр Canvas героя. Для сигнала из React вызови `window.__yaasPreloader.ready()` из места, где сцена героя реально отрисовала первый кадр с текстурами. Найди это место в `HeroScene`/`HeroCanRig`/`deferredLoad.js`. Если с текстурами трудно, используй `onCreated` + `useProgress` из drei.
- Жёсткий лимит: 2000 мс от начала навигации (`performance.now()`). Прелоадер скрывается по готовности или по лимиту, что наступит раньше. Минимум показа ≈ 600 мс, чтобы не мигал.
- Счётчик привязан к этим срокам: идёт плавно к ~90% за ожидаемое время, после `ready()` быстро (≈250 мс) добегает до 100, после чего запускается скрытие.
- Скрытие: fade оверлея ≈ 400 мс (opacity), затем удалить узел из DOM, разблокировать скролл и resolve `done`. Сразу после этого стартует существующая анимация: влетают банки и появляется текст.
- Страницы без героя (`/catalog`, `/catalog/:slug`, `/contacts` и др.): если за 300 мс после монтирования никто не вызвал `ready()`, готовность = `fonts.ready` + `window load`, всё в пределах того же лимита 2 с.
- При SPA-переходах внутри сайта прелоадер не показывается (он живёт только в `index.html` при первой загрузке).
- `prefers-reduced-motion: reduce` — лента стоит на месте, счётчик работает, fade остаётся.
- Оверлей: `aria-hidden="true"` для декора, счётчик в `role="status"`, `aria-live="polite"`.

## Ограничения
- Делай только то, что описано. Никаких рефакторингов, новых фич и правок несвязанных компонентов.
- Не добавляй зависимостей в `dependencies`. Перед любой установкой пакета остановись и спроси.
- Не меняй анимацию входа героя, GSAP-пины, ScrollTrigger и `useHeroScale` — только точку старта входа.
- Не удаляй и не перезаписывай существующие файлы в `public/`, только добавляй новые в `public/images/preloader/`.

## Критерии готовности (проверь сам и отчитайся цифрами)
1. `npm run build` проходит без ошибок и новых warning'ов.
2. Lighthouse (mobile + desktop) на главной до и после изменений: LCP не хуже чем +100 мс, CLS = 0, TBT не вырос. Покажи таблицу «до/после».
3. На Slow 4G (DevTools throttling) прелоадер скрывается не позже 2,0 с; на быстром соединении — раньше, без мигания.
4. После скрытия оверлея ни на одном кадре не видно подгружающихся текстур, фона или заголовка, а банки влетают и текст появляется как сейчас.
5. Скриншоты оверлея на 1920×1080, 1440×900, 1024×768, 390×844 (Playwright, Chromium уже установлен): заголовок ровно во всю ширину контейнера, отступ сверху до заголовка равен отступу снизу от счётчика, банки по размеру как в макете.
6. Размер новых картинок: перечисли файлы и вес.
